# 交通信号控制系统SCATS/SCOOT

## 一、概述

交通信号控制系统是城市交通管理的核心手段之一。传统的固定配时信号控制无法适应实时变化的交通需求，因此自适应交通信号控制系统应运而生。在全球范围内，SCATS和SCOOT是两个最具代表性的自适应交通信号控制系统，分别源自澳大利亚和英国，在世界多个国家和城市得到广泛应用。

自适应信号控制系统的核心思想是：通过实时检测交通流数据，动态调整信号配时参数（周期、绿信比、相位差），使信号控制方案始终适应当前的交通需求，从而最大限度地减少车辆延误和停车次数，提高交叉口和路网的通行效率。

## 二、信号控制基本参数

在介绍SCATS和SCOOT之前，需要了解交通信号控制的三个核心参数：

**周期（Cycle Length）**：信号灯完成一个完整循环所需的时间，单位为秒。周期过短会导致频繁启停，周期过长会导致等待时间增加。合理的周期设置需要平衡通行效率和延误。

**绿信比（Split）**：一个周期内各相位绿灯时间的分配比例。绿信比的设置应与各方向的交通流量成正比，流量大的方向分配更多绿灯时间。

**相位差（Offset）**：相邻交叉口同一方向绿灯起始时刻的时间差。通过合理设置相位差，可以实现"绿波"效果，使车辆在主干道上连续通过多个绿灯路口。

## 三、SCATS系统

### 3.1 系统概述

SCATS（Sydney Coordinated Adaptive Traffic System，悉尼自适应交通控制系统）由澳大利亚新南威尔士州道路交通管理局（RTA）开发，于20世纪70年代开始研发，80年代投入实际使用。SCATS是全球最早大规模部署的自适应交通信号控制系统之一。

### 3.2 技术原理

SCATS采用基于规则的在线实时优化方法，不依赖精确的交通流模型，而是通过实际检测数据直接调整信号配时参数。其核心优化指标是**饱和度（Degree of Saturation，DS）**，即实际到达流量与通行能力的比值。

SCATS的优化过程分为两个层次：

**战略层（区域协调）**：在区域范围内优化各交叉口之间的协调关系，确定公共周期和相位差。SCATS将多个相邻交叉口划分为一个"子系统"，子系统内的交叉口采用相同的周期长度，通过优化相位差实现绿波协调。

**战术层（单个交叉口）**：在单个交叉口层面优化绿信比分配。SCATS根据实时检测的饱和度，动态调整各相位的绿灯时间，使各方向的饱和度趋于均衡。

### 3.3 系统架构

SCATS采用三级层次控制架构：

**中央监控中心（Central Control，CC）**：负责全局监控和区域间协调。中央监控中心可以查看所有路口的运行状态，进行远程干预和参数调整。

**区域控制中心（Regional Traffic，RT）**：负责区域内多个路口的协调优化。每个区域控制中心管理若干个子系统，子系统内的交叉口共享公共周期。

**路口信号控制器（Local Signal，LS）**：负责单个交叉口的信号控制执行。路口控制器接收区域控制中心的指令，同时具备本地优化能力，在通信中断时可以独立运行。

### 3.4 检测器布置

SCATS的检测器通常安装在**停车线后方**（近端检测），即车辆等待红灯的位置。这种布置方式可以直接检测排队车辆的存在和离开，用于计算饱和度。每个车道至少需要安装一个检测器。

### 3.5 技术特点

- 不依赖精确的交通流模型，适应性强
- 采用饱和度作为核心指标，对过饱和交通有较好的处理能力
- 检测器布置在停车线后方，安装维护方便
- 系统响应速度快，适合交通需求快速变化的场景
- 全球已有超过40个国家和地区的170多个城市部署使用

## 四、SCOOT系统

### 4.1 系统概述

SCOOT（Split Cycle Offset Optimisation Technique，绿信比-周期-相位差优化技术）由英国交通研究实验室（TRL，前身为TRRL）与PEEK Traffic等机构联合开发，于20世纪80年代投入使用。SCOOT是全球应用最广泛的自适应交通信号控制系统之一。

### 4.2 技术原理

SCOOT采用**交通模型驱动**的在线实时优化方法。系统通过微观交通流模型预测不同参数组合下的延误和停车次数，选择使总延误和停车次数最小的参数组合。

SCOOT的优化策略是**小步增量调整**：每次对周期、绿信比或相位差进行±4秒的微调，通过观察调整后的效果逐步趋向最优。这种渐进式优化方法避免了大范围参数调整可能带来的风险。

SCOOT分别对三个参数进行独立优化：

**绿信比优化（Split Optimization）**：根据各方向的到达流量和排队长度，动态调整各相位的绿灯分配。

**周期优化（Cycle Optimization）**：根据交叉口的总体负荷水平，调整周期长度。当负荷增大时延长周期，负荷减小时缩短周期。

**相位差优化（Offset Optimization）**：根据相邻交叉口之间的车辆到达模式，优化相位差以减少延误和停车。

### 4.3 系统架构

SCOOT同样采用三级层次控制架构：

**中央计算机**：运行SCOOT优化软件，负责全局数据处理和优化计算。中央计算机需要较强的计算能力，以实时处理大量检测数据并运行交通模型。

**区域/子区域控制**：协调多个交叉口的信号配时，实现区域层面的交通优化。

**交叉口信号控制器**：执行信号配时方案，采集本地检测数据并上传至中央系统。

### 4.4 检测器布置

SCOOT的检测器通常安装在**上游位置**（距停车线约100-150米处）。这种布置方式可以在车辆到达交叉口之前就检测到车辆的到来，为系统提供更充裕的响应时间。检测器采集的数据包括流量、占有率和车辆到达时间等。

### 4.5 核心模块

SCOOT系统包含三个核心模块：

**交通模型模块**：基于实时检测数据建立微观交通流模型，模拟车辆在路网中的运动过程，预测排队长度、延误等指标。

**优化模块**：分别对绿信比、周期和相位差进行优化计算，选择使目标函数（延误、停车次数的加权和）最小的参数组合。

**数据库模块**：存储历史和实时数据，用于模型校准和趋势分析。

### 4.6 技术特点

- 基于交通模型的优化方法，理论基础扎实
- 小步增量调整策略，运行稳定可靠
- 检测器布置在上游，可提前预判交通需求
- 适合未饱和交通流条件
- 全球已有超过200个城市部署使用

## 五、SCATS与SCOOT对比

| 对比维度 | SCATS | SCOOT |
|----------|-------|-------|
| 起源 | 澳大利亚悉尼 | 英国 |
| 优化方式 | 基于规则/饱和度 | 基于交通模型 |
| 检测器位置 | 停车线后方（近端） | 停车线上游（远端） |
| 参数调整 | 大范围搜索最优组合 | 小步增量调整（±4秒） |
| 对模型依赖 | 低 | 高 |
| 适用场景 | 饱和及过饱和交通 | 未饱和交通 |
| 主要优化指标 | 饱和度 | 延误、停车次数 |
| 全球部署 | 170多个城市 | 200多个城市 |
| 响应速度 | 快 | 中等 |
| 通信中断处理 | 路口独立运行 | 路口独立运行 |

## 六、发展趋势

### 6.1 AI赋能信号控制

近年来，基于深度强化学习（DRL）的信号控制方法受到广泛关注。与传统自适应控制相比，AI信号控制可以学习更复杂的交通模式，实现更精细的配时优化。百度、阿里等企业已在多个城市部署AI信号控制系统。

### 6.2 车路协同融合

随着V2X技术的发展，信号控制系统正在与车路协同系统深度融合。通过V2I通信，信号灯可以直接向车辆推送配时信息，实现绿波车速引导；同时，车辆的实时位置和速度数据也可以反馈给信号系统，提供更精确的交通需求信息。

### 6.3 区域协调优化

未来的信号控制将从单点优化向区域协调优化发展，通过考虑路网层面的交通流分布和传播规律，实现全局最优的信号配时方案。数字孪生技术为区域协调优化提供了仿真验证平台。

### 6.4 多模式交通协调

现代城市交通包含小汽车、公交、非机动车、行人等多种交通模式。未来的信号控制系统需要综合考虑各种交通模式的需求，实现多模式交通的协调优化，例如公交优先信号控制、行人过街时间优化等。
